Files: Each case has baseline.csv (summary) and baseline.samples.csv (individual trials).
       baseline.environment.json records versions, hashes, inputs, affinity and settings.

Rows: Five independent processes per language/configuration; shuffled order.
      BAML medium/off, Rust, Go, CPython, Node/V8 and Bun/JavaScriptCore.

Time: wall_ms and cpu_ms are per job; startup uses a complete invocation.
      HTTP cpu_ms is CPU per correct response, including CPU spent on failed work.
      Other time columns are medians; min/max columns show observed spread.
      Raw process_wall_ms also includes controller preparation/validation waits.
      Raw process_cpu_ms counts only the benchmark process, including warmup/shutdown.
      Use the summary columns for comparisons.

Memory: peak_rss_mib is the largest process high-water RSS across the five trials.
        A small native observer prevents the launcher's RSS from contaminating it.

Size: application_bytes is the executable or script + driver.
      runtime_bytes adds the interpreter; Python includes its stdlib and dependencies.
      mapped_libraries_bytes adds loaded shared libraries not already counted.
      bundle_bytes is their sum, uncompressed. This is the observed benchmark bundle,
      not a minimal deployment or complete OS image. Per-run artifact.json lists files.
      Rust/Go applications are stripped; BAML/Node/Bun use their supplied release files.

HTTP: Offered rates are fixed, not measured maximum capacity. Each trial sends 1000
      requests; the goodput deadline is an experimental 100ms. failures/late are totals
      across trials. Client lag and timeouts remain in latency percentiles. RPS counts
      completions inside the scheduled window; drain_s records the additional wait.
      CPU includes work through drain. Thirty timeouts occurred in the 100 RPS trials;
      a follow-up reproduced a stall in TCP connection setup, before sending HTTP.

Ratios: *_vs_node divides by Node's median for the same scenario; lower is better.

Scope: Spark shared host; benchmark CPUs 15,16; client CPU 5; GOMAXPROCS=2 and
       TOKIO_WORKER_THREADS=2. Affinity limits placement; it does not reserve CPUs.
       Results include result encoding and pipe transfer. GC uses runtime defaults.
       Fresh processes use warmed OS caches; job counts are calibrated per runtime.
       BAML is the installed 0.20.2-nightly.20260923.a VM release, not the newer checkout
       or an AOT backend. Telemetry settings are requested; event completeness is
       unverified. GC pauses and incremental compiler latency are not measured here.

Win: Lower CPU per correct application job/request with preserved behavior/telemetry,
     within declared latency and memory limits. Report size/build-cost regressions.
     Use the observed spread; a small difference inside it is inconclusive.
